# commit

변경 사항을 논리 단위로 묶어 커밋한다.

---

## 1. 현황 파악

`git status`와 `git diff HEAD`를 실행해 변경 파일과 내용을 확인한다.

## 2. 그룹핑 제안

변경 파일을 논리적 단위로 묶어 유저에게 제안한다.  
예: calculator 버그 수정 / docs 업데이트 / 이미지 추가 등은 각각 분리.

- `static/` 또는 `image/` 하위 untracked 파일이 있으면 포함 여부를 먼저 묻는다.
- `memo.txt`는 다른 변경과 함께 커밋할 때 메시지에 언급하지 않는다. 단독 커밋일 때만 최소한의 메시지 사용.
- 로그 파일(`*.log`)은 커밋하지 않는다.

## 3. 커밋 메시지 초안 작성

각 그룹에 대해 메시지 초안을 보여주고 유저 승인을 받는다.  
승인 없이 커밋하지 않는다.

### 메시지 형식

```
[캐릭터명] 추가
[stat명] 구현
feat: 기능 추가 내용
fix: 버그 내용
perf: 성능 개선 내용
refactor: 리팩터링 내용
docs: 문서 업데이트 내용
chore: 설정·도구 변경
```

## 4. 커밋 실행

승인된 그룹을 순서대로 커밋한다.
