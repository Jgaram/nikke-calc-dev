# commit

변경 사항을 논리 단위로 묶어 커밋한다.

인자: `$ARGUMENTS`

- 인자 없음 → **세션 모드**: 이 세션에서 건드린 파일만 커밋
- 인자 = `all` → **전체 모드**: 모든 미커밋 변경 파일을 조사해 커밋 준비

---

## 공통 1단계 — 현황 파악

`git status`와 `git diff HEAD`를 실행해 전체 미커밋 변경 파일 목록을 확인한다.

---

## 세션 모드 (인자 없음)

### 2. 세션 구분

변경 파일을 두 범주로 나눈다:

- **이 세션에서 변경한 파일** — 현재 대화에서 직접 읽거나 수정한 파일
- **이 세션에서 건드리지 않은 파일** — 미커밋이지만 이 대화와 무관한 파일

후자는 커밋 대상에서 **자동 제외**한다. 목록만 간략히 표시하고 넘어간다.

### 3. memo.txt 처리

`memo.txt`가 변경되어 있으면 자동으로 커밋에 포함한다. 유저에게 묻지 않는다.  
다른 변경과 함께 커밋할 때는 메시지에 언급하지 않는다. 단독 커밋 시만 최소 메시지 사용.

### 4. 제외 파일

- 로그 파일(`*.log`)은 커밋하지 않는다.
- `static/` 또는 `image/` 하위 untracked 파일은 포함 여부를 먼저 묻는다.

### 5. 그룹핑 및 메시지 초안

커밋할 파일을 논리적 단위로 묶어 메시지 초안과 함께 유저에게 제안한다.  
승인 없이 커밋하지 않는다.

### 6. 커밋 실행

승인된 그룹을 순서대로 커밋한다.

---

## 전체 모드 (인자 = `all`)

### 2. 전체 변경 조사

미커밋 파일 전체를 대상으로 한다. 세션 구분 없이 모든 변경을 포함한다.  
각 파일에 대해 `git diff HEAD -- <file>`로 내용을 확인해 변경 의도를 파악한다.

### 3. memo.txt 처리

세션 모드와 동일: 변경되어 있으면 자동 포함, 유저에게 묻지 않는다.

### 4. 제외 파일

- 로그 파일(`*.log`)은 커밋하지 않는다.
- `static/` 또는 `image/` 하위 untracked 파일은 포함 여부를 먼저 묻는다.

### 5. 그룹핑 및 메시지 초안

모든 변경 파일을 논리적 단위로 묶어 커밋 플랜 전체를 한눈에 표시한다.  
예시:

```
[커밋 1] feat: ...
  - ui/foo.py
  - calculator/bar.py

[커밋 2] fix: ...
  - data/baz.json
```

승인 없이 커밋하지 않는다.

### 6. 커밋 실행

승인된 그룹을 순서대로 커밋한다.

---

## 공통 — 메시지 형식

```
[캐릭터명] 추가
[stat명] 구현
feat: 기능 추가 내용
fix: 버그 내용
perf: 성능 개선 내용
refactor: 리팩터링 내용
docs: 문서 업데이트 내용
chore: 설정·도구 변경
```
