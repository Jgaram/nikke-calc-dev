# commit

변경 사항을 논리 단위로 묶어 커밋.

**승인을 묻지 않는다.** 이 스킬의 호출 자체가 커밋 승인이다.
그룹핑·메시지를 정했으면 확인 없이 곧바로 `git commit`까지 실행한다.

커밋 플랜도 보여주지 않는다. 알아서 판단해 커밋하고, 끝난 뒤 결과만 한두 줄로 보고한다.

금지 행동:
- "이렇게 커밋할까요?" / "진행할까요?" 같은 확인 질문
- AskUserQuestion·ExitPlanMode 호출
- 커밋 전에 플랜·메시지 초안을 출력하는 것
- 커밋 계획만 출력하고 턴을 종료하는 것

예외: 스테이징 대상을 도저히 판단할 수 없을 만큼 변경이 모호할 때만 질문한다.

**인자**:
- 없음 → **세션 모드**: 이 세션에서 건드린 파일만
- `all` → **전체 모드**: 모든 미커밋 변경 파일

---

## 공통 1단계 — 현황 파악

`git status`와 `git diff HEAD` 실행 → 전체 미커밋 변경 파일 목록 확인.

---

## 세션 모드

### 2. 세션 구분

- **이 세션에서 변경한 파일** — 현재 대화에서 직접 읽거나 수정한 파일
- **이 세션에서 건드리지 않은 파일** — 미커밋이지만 이 대화와 무관

후자는 커밋 대상 **자동 제외**.

### 3. 제외 파일

- `*.log` 커밋 안 함.
- `static/` 또는 `image/` 하위 untracked 파일은 자동 제외.

### 5. 그룹핑 및 커밋 실행

논리적 단위로 묶어 메시지를 정하고, 출력 없이 바로 순서대로 커밋한다.
커밋 후 어떤 커밋이 생겼는지만 한두 줄로 보고.

---

## 전체 모드 (all)

### 2. 전체 변경 조사

미커밋 파일 전체 대상. 세션 구분 없음. 각 파일 `git diff HEAD -- <file>`로 변경 의도 파악.

### 3. 제외 파일

- `*.log` 커밋 안 함.
- `static/` 또는 `image/` 하위 untracked 파일은 자동 제외.

### 5. 그룹핑 및 커밋 실행

모든 변경 파일을 논리적 단위로 묶어 메시지를 정하고, 플랜 출력 없이 바로 순서대로 커밋한다.
커밋 후 어떤 커밋이 생겼는지만 한두 줄로 보고.

---

## 메시지 형식

```
[캐릭터명] 추가
[stat명] 구현
feat: 기능 추가 내용
fix: 버그 내용
perf: 성능 개선 내용
refactor: 리팩터링 내용
docs: 문서 업데이트 내용
chore: 설정·도구 변경
```
